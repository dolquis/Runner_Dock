# Runner Dock IPC・データモデル契約の入口

UI と Agent は型付きの許可リストだけで繋がる。この境界が片側だけ変わると実行時にしか壊れず、SQLite の schema も migration を欠けば既存ユーザーの環境でだけ落ちる。このスキルは仕様を複製せず、読む節と越えてはならない線だけを示す。

## 読む

1. 触れる契約を先に特定し、`docs/10_IPC_DATA_MODEL.md` の該当節だけを読む。「通信面」「フレーム形式」「メッセージ例」「メソッド一覧」「型の決まり」「SQLiteの初期スキーマ例」「トランザクションと回復」「エラー契約」「配信・互換性」から選ぶ。
2. 責務の置き場所に触れるなら `docs/03_ARCHITECTURE.md` の「構成と責務」「状態の管理」「秘密情報の境界」を読む。
3. UI へ出る値に触れるなら `docs/11_UX_SPEC.md`「UI 状態の受入条件」を読む。

## 守る

1. メソッド、フィールド、エラーコード、列を変えたら、送信側と受信側の両方を同じ PR で揃える。片側だけ変えない。
2. 型付きの許可リストを迂回しない。汎用 `exec` 相当のメソッド、未知 JSON の無検証 cast、`any` 相当の型を足さない。
3. schema を変えたら migration を同じ PR で足し、既存 DB の読み込み経路が追随していることを確認する。ロールバック不能な破壊的 migration を避ける。
4. 複数テーブルの更新は単一トランザクションに入れる。中断時に不整合が残る経路を作らない。
5. 失敗を成功として返さない。エラーは型付きで表し、握り潰さない。取得できなかった値を既定値で埋めず `Unknown` を保つ。
6. IPC の payload、DB の列、エラーメッセージに token や Runner 資格情報を入れない。
7. 版の異なる UI と Agent が同居しうる経路では、版の判定と既定の挙動を定義する。

## 検証する

- 差分を `ipc-contract-checker` に read-only で読ませ、返った指摘を実ファイルで確認する。型の再生成や migration の適用は親が実行する。
- 契約を変えたら `docs/10_IPC_DATA_MODEL.md`、該当 ADR、`docs/20_TRACEABILITY.md` のうち失効した記述を同じ PR で直す。
- `docs/12_TEST_PLAN.md`「必須試験カタログ」の契約テストに対応する項目があれば、同じ PR で追加または更新する。
