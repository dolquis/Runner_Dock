# 11. UI/UX仕様

**区分:** 画面・操作契約 / **初期言語:** 日本語、内部メッセージキーは多言語対応

## 1. 画面構成

左ナビゲーションは「ホーム」「Runner」「Workflow」「ログ・診断」「設定」。初回だけセットアップウィザードを表示します。常時監視に必要な表示と高度な設定を分け、初回から全設定を露出しません。

ウィンドウサイズは初期目標960×680、最小800×600。OS表示倍率100/150/200%、キーボード、スクリーンリーダーで確認します。値はプロトタイプ後に調整可能です。

## 2. 初回セットアップ

| 画面 | 入力・表示 | 次へ進める条件 |
|---|---|---|
| 利用上の注意 | self-hostedの信頼境界、私用PCでの残存リスク | 確認と同意 |
| PC診断 | Windows/WSL2/distro/空き容量/ネットワーク | fatalとwarningを区別 |
| GitHub接続 | Device Flow、権限、token期限 | 対象scopeが確認できる |
| repo選択 | 自分が管理するprivate repo | アクセスと管理権限を確認 |
| 実行環境 | Windows、既存/専用WSL、Linuxユーザー | root通常運用を選べない |
| 変更計画 | 追加・変更・保存先・必要権限・再起動 | plan hash付きで承認 |
| 構築 | 段階別進行、取消、部分成功 | 各段階の結果が記録される |
| 構築完了 | Local/GitHub両状態、スモークテスト導線 | 未確認を成功表示しない |

GitHub管理tokenとselector用read tokenは別の設定です。利用者に理由を説明し、期限を混同させません。

## 3. ホーム画面の情報構造

```text
Runner Dock                    PC: DESKTOP-XXXX
Node: 部分稼働                 [Nodeを起動] [停止を要求]

Windows Runner
  ローカル: 稼働中       GitHub: online / idle
  GitHub確認: 12秒前     次の動作: 受付可能という観測

Ubuntu / WSL2
  WSL Guest: 応答なし    GitHub: 状態不明
  理由: Guestとの接続が切断されました
  [Ubuntuのみ再試行] [診断を見る]

PC全体 CPU / メモリ / ディスク空き
※ WSLとWindowsは同じ物理資源を共有します。
```

緑は確認済みReady、黄はBusy/処理中、赤は確認済み停止や障害、灰はUnknown/staleです。色の意味だけで状態を表現せず、テキストとアイコンを併記します。

## 4. Start Node

起動ボタン押下で直ちに受付表示を出し、操作IDを作ります。Windows→Ubuntuと固定で全部を待たず、独立した進捗を並べて表示します。API照会を画面スレッドで同期実行しません。

片側成功時の表示は「1/2稼働」。API接続に失敗してもローカル起動が成功していれば「プロセス起動済み、GitHub確認未完了」です。成功メッセージで上書きしません。

設定後は起動アイコンから`start_on_launch`を使えます。自動起動設定は初回に同意を取り、GUI表示・Agent起動・Runner起動を別々に制御できるようにします。

## 5. Stop Node

初期の主ボタンは「停止を要求」。Busyなら「実行が終わるまで停止を待つ」と表示します。ただし受付を完全に停止できる保証はないため、詳細欄に競合の可能性を表示します。

強制停止は別ボタンです。確認文の例:

> Ubuntu Runnerでジョブ実行中という観測があります。強制停止すると実行が中断される可能性があります。対象はこのRunnerのみです。Ubuntu全体は終了しません。

APIがUnknownなら「実行中か確認できません」を明示し、同じ確認強度にします。distro終了や削除を同じボタンに混ぜません。

## 6. GUIを閉じる

初回の閉じる操作では「画面を閉じてもRunnerは動作を続けます」を説明します。選択肢は「画面だけ閉じる」「停止画面へ戻る」。閉じるアイコンが無確認の停止操作になってはいけません。

Agentが別プロセスであることは実装で保証し、タスクトレイへ隠しただけのGUIをdaemonと呼びません。Agentを終了する操作は設定またはトレイメニューに別に用意します。

## 7. Workflow画面

入力はrepoとWorkflowファイル、生成対象OS、trusted ref、hosted許可、monitor token名。表示は対応可能/非対応構文、変更前後の実行先、必要Secret、推定される動作、差分です。

MVPのボタンは「テンプレートを保存」。後続の「ファイルへ適用」「PRを作成」は未実装なら非表示にします。使えない機能を押せる完成画面として見せません。

`force_hosted`の利用、判定後の停止でキューに残る場合、selectorのhosted利用が発生することを、適用前に説明します。

## 8. ログと診断

ログは仮想化リスト、検索、level、Runner、Operationで絞込みます。ANSI escapeやHTMLを生のまま解釈しません。行数・保存量・保持期間と切捨て件数を表示します。

診断書き出しは含まれるファイル一覧をプレビューし、資格情報・workspace・個人pathの扱いを確認できます。UIにtoken全表示ボタンは作りません。

## 9. 設定

初期設定に置く項目は、ログオン時Agent起動、起動時Runner起動、ログ保持、API監視頻度、hosted許可、専用distro終了の既定、更新通知です。

WSLのCPU/RAMは「WSL2全体設定」と表示します。Runner単体の制約とは別の画面にし、既存設定への影響を見せます。Windows/Linuxを同時onlineにしたまま全repoのジョブを厳密に1つへ制限するUIはMVPでは出しません。

## 10. UI状態の受入条件

Loading、Empty、Ready、Busy、Partial、Offline、Unknown、PermissionDenied、RateLimited、RestartRequiredを個別にfixture化します。Unknownをエラーの赤だけで表さず、確認できていないことが分かる表示にします。

表示テストはMock APIだけでなく実Windows WebViewでも実施します。高頻度メトリクスでログ画面全体を再レンダーさせない、再接続で購読が増殖しない、二重クリックで二重登録されないことを確認します。
