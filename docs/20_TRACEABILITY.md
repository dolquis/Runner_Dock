## 4. 段階別の扱い

P0要件はMVP公開ゲート、P1/P2はその機能の公開時に合格させます。後続機能を実装しないMVPで、その試験を合格扱いにしません。LF-027は任意のbroker検討であり、MVP必須要件へ紛れ込ませません。

資料の確認と設計書作成は完了していますが、G1〜G6の製品検証は未実施です。特にWindows/WSL実機、GitHub App実認証、公式Runner更新、実GitHub Actions上でのWorkflow実行は、この文書作成環境では実施していません。

## 5. 文書一式に対する静的・模擬検査

**実施日:** 2026-09-19 / **対象:** 同梱Markdownと掲載したサンプル / **環境:** 文書作成用Linuxコンテナ

| 検査 | 実施結果 |
|---|---|
| UTF-8・NUL/置換文字・コードフェンス | 24ファイル、25コードブロックを確認。検出エラーなし |
| 相対リンク・明示アンカー | 171件の参照先を確認。リンク切れなし |
| 仕様IDと追跡表 | FR 22件、NFR 12件、LF 29件、TC 45件の定義・参照を照合 |
| 出典参照 | S01〜S34の34件を定義。本文からの未定義出典参照なし |
| 掲載WorkflowのYAML | `on`を文字列キーとして構造解析。job/outputs/Secretの配置を確認 |
| 掲載selectorのPython/Bash | PythonのAST/compile、Bashの`-n`構文検査に合格 |
| selectorの模擬API試験 | 25ケースに合格。オンライン/Busy/型不正/ID・label不一致/HTTP障害/認証欠落等 |
| 掲載SQLのSQLite検査 | 8テーブルのDDLを実行。外部キー、重複、CHECK、scope分離、整合性等の8項目に合格 |

模擬API試験では外部ネットワークを使わず、既知の応答と障害を注入しました。GitHub式の実評価、実際の認可、jobの割当は検証していません。値が不正な応答はローカルを選ばないことを確認しています。

検査で見つけた「JSON応答の最上位やlabelsの型が不正なときの例外漏れ」は、掲載selectorへ型検査を追加して修正し、再検査しました。検査コードは文書作成用であり、アプリ実装や製品テストスイートは本パッケージに含みません。

検査は文書と掲載例を対象としたものです。GitHub上でworkflowが受理・実行されたこと、Windows named pipeが安全に動くこと、WSLのGuestが常駐できることを証明するものではありません。
