# 01. プロジェクト憲章

**区分:** 製品方針 / **状態:** 独自開発方針は決定、名称・配布方針は提案

## 1. 一文で表す製品

自宅Windows PCが持つWindowsとWSL2 Linuxの実行環境を、GitHub Actions用の1つの「CIノード」として構築・起動・監視・保守するデスクトップアプリ。

Runnerを置くことより、**使いたいときに起動し、使えない理由が分かり、既存のPC作業を壊さず停止できること**を重視します。

## 2. 解決する問題

導入時にはRunner登録、必要ツール、WSL、権限、認証が分散しています。運用時には「サービスは動いているのにGitHubではoffline」「GUIを閉じたらLinux側だけ停止」「停止中にジョブを受けた」など、複数の状態を横断して考える必要があります。

本製品はその横断管理を担当し、ビルドそのものはGitHub公式Runnerへ委譲します。GitHub Actionsエージェントのプロトコルやビルドエンジンを独自実装しません。

## 3. 対象ユーザー

初期対象は、Windows 11 x64 PCを持ち、自分のGitHubリポジトリのWindows/Linuxビルドを動かしたい個人開発者です。PowerShellやWSLの高度な知識がなくても、確認と許可をしながら導入できる体験を目標にします。

最初の受入環境はWindows 11 x64 + WSL2 + Ubuntu 24.04 LTS x64です。これは製品のテスト対象を限定する決定であり、GitHubやWSLの最新OS・全サポート範囲を表すものではありません。[S01](19_SOURCES.md#s01)

組織での共用、複数PC、外部開発者の任意コード実行、24時間無人稼働は後続段階です。

## 4. 製品の核

| 核 | 利用者から見える価値 |
|---|---|
| Node単位の管理 | 2種類のOSを別々のスクリプトで起動しなくてよい |
| 段階的なセットアップ | 何が足りないか、何が変更されるかを確認できる |
| 二重ヘルス | ローカル稼働とGitHub到達性を混同しない |
| 事前ルーティング支援 | PC停止時のhosted利用をWorkflowに組み込める |
| 明示的な安全・課金方針 | 未信頼コードや意図しない課金を既定の挙動にしない |
| 環境を壊さない操作 | 既存WSL、サービス、コード、キャッシュを無断変更しない |

## 5. 競合・参考実装との関係

HomeRunは先行事例として、導入手順、daemon分離、Runner操作、ログ表示などの問題設定を学びます。READMEと設計資料で確認できた範囲は[参考実装レビュー](18_REFERENCE_REVIEW.md)に限定して記録します。[S28](19_SOURCES.md#s28)[S29](19_SOURCES.md#s29)

市場に競合が存在しない、世界初である、HomeRunに特定機能が絶対にない、という主張はしません。コード・データモデル・プロトコル・画面設計は本プロジェクトで独立して決めます。

## 6. 非目標

本製品はGitHub-hostedと完全に同一のOSイメージを提供するものではありません。セットアップ支援とビルド再現性チェックは行いますが、`windows-latest`の全プリインストールツールを複製しません。

また、私用PCを任意コードから完全隔離するサンドボックス、GitHubのジョブスケジューラの置き換え、実行途中のジョブの無停止移行、CI料金の削減保証は提供しません。

## 7. 成功の定義

初期MVPの成功は、所有者の承認済みprivate repoに対して、Windows/Linuxの両Runnerを構築・起動・監視・停止し、PCが使えない場合の事前hosted選択を検証できることです。テスト環境での実測結果を残します。

ユーザー満足の指標は、初回構築の完了率、起動・停止失敗の説明可能性、復旧時の再登録不要率、誤停止件数、診断可能なエラー割合です。目標値はベータ利用で測定して調整し、未測定の性能を広告しません。

## 8. 費用の扱い

確認時点のGitHub資料ではself-hosted実行とpublic repoの標準hosted実行は無料とされていますが、private repoのhosted超過分やストレージ等には別の課金があります。[S20](19_SOURCES.md#s20)

製品は請求額を保証せず、hosted許可の同意、ルーティング理由、適用前後の実行先を表示します。金額推定を将来導入する場合は、電力・稼働時間・無料枠・為替の前提を分離して記録します。
